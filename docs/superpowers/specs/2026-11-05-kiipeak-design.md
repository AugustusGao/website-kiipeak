面向普通中文科技爱好者，提供世界范围内具身智能和机器人前沿进展的精选解读。以看懂新成果的意义与实际局限为目标，不追求快讯数量。

## 2. 建设方式与取舍

已讨论两种方式：
- VPS 采集、调用 Codex、发布：不依赖个人电脑，需要服务器端登录和维护账号凭据，受共享额度及网络影响。用户选择此方式。
- 个人电脑调用 Codex、上传 VPS：凭据留在本机，但关机影响定时更新，未选。

架构由实施者提议：Nginx 提供静态页面；Python 负责采集、任务编排、SQLite 元数据和页面生成；独立 Codex CLI 任务负责选题、撰文和核验。管理服务只监听本机，经 SSH 隧道访问。无需为初期网站单独引入 WordPress、公共数据库或复杂前端运行服务。
理由：前台与 AI 任务解耦，生成失败不影响访问，维护负担小；代价是编辑管理功能须按需求实现，初期功能从简。

## 4. 内容范围与编辑规则

范围：人形机器人、家庭与服务机器人、工业应用、机器人学习与具身 AI。全球覆盖，不限海外；优先一手英文及其他语种材料。
优先来源：企业官方技术博客与发布、大学/研究机构项目页、论文摘要与原文、官方演示。新闻媒体作线索或补充，传闻不直接作为事实发布。
首批仅接入约 10～20 个明确可采集来源，通过 RSS、公开 API 或允许访问的网页采集；来源清单在实施时核对，记录采集方式、可靠性与失败状态。
不绕过登录、付费墙或访问限制。正文独立中文编写，以必要短引用、来源链接或允许嵌入的演示解释事实，不整篇翻译搬运，不默认转载来源图片。

每篇建议 800～1500 中文字，按材料价值调整，不为凑字扩写。包括：
- 中文标题和简短导读；
- 发生了什么、为什么值得关注；
- 已展示能力、演示条件与未证明的能力；
- 距离实用化的障碍，缺证据时明确未知；
- 来源链接、事件时间、本站发布时间、更新记录及 AI 整理标识。
不得编造价格、上市日期、性能、引语或观看视频后才可知的细节。仅有文字或视频说明时，明确依据范围。

## 5. 自动运营流程

定时采集 → 清洗及缓存 → 规则去重 → Codex 筛选与中文解读 → 单独核验任务 → 确定性发布检查 → 生成静态页面并原子切换。

采集不调用 AI。以规范化 URL、内容指纹、标题和实体/事件信息减少重复；模型辅助合并同一事件，无法确定时保留待处理，允许重大后续作为更新。
每次交给 Codex 有长度上限的来源材料和候选列表，避免把整个历史库反复输入。AI 接收的网页一律视作不可信资料，网页中的指令不得触发执行或发布操作。
生成与核验分别执行，第二阶段逐项核对关键事实与证据；模型自评通过不能代表事实无误。发布程序仍检查必填字段、来源引用、重复、日期、危险 HTML 与发布限额。事实无依据、来源冲突或内容不足则进入待处理队列。
文章状态：候选、草稿、待处理、已发布、已撤回；保存失败原因、来源版本和变更历史。
更新已发布文章需记录更正说明。自动发布内容不允许模型修改系统配置、安装软件或执行任意运维命令。

## 6. 调度、额度与故障处理（提议默认值）

使用 VPS systemd timer 调度，不依赖 Codex 桌面应用是否运行；统一时区 Asia/Shanghai。
普通采集每 2 小时一次；编辑批次每天 05:00、20:00 启动（北京时间 Asia/Shanghai），各最多发布 1 篇；这是开始处理时间，文章在撰写与核验通过后发布，每天最多 2 篇。无合适选题时允许零发布，重大消息初期不单独插队。
每批默认最多 1 次撰写调用和 1 次独立核验调用；初期每天最多 4 次此类调用，首次试运行另计。这个上限限制任务次数，不能保证固定额度消耗或一定够用。
每次调用设时限、输入长度和输出上限，并记录可获得的用量信息。共享订阅额度也用于用户日常 Codex 操作，不能承诺每 5 小时可完整跑一轮或达到固定产量。
遇到额度限制：记录可获取的重置时间，在后续允许窗口继续；否则退避至下一正常批次，不高频重试。身份失效则暂停 AI 任务并在管理页报告，等待重新授权。网络错误有限重试；永久拒绝不自动切换代理或付费 API。
任务加互斥锁，重启补跑最多一个编辑批次，防止累计任务耗尽额度；同一来源/事件处理可重入，发布具幂等性。

## 7. 网站与管理范围（提议默认值）

暂定品牌 KiiPeak，中文副标题“看懂全球机器人前沿”。域名以 https://kiipeak.com 为主，www 和 HTTP 重定向至主域 HTTPS；HTTP 保留证书验证所需路径。
前台：精选首页、分类列表、文章详情、按标题/摘要的站内搜索、来源与编辑说明、RSS、sitemap、robots、404。移动端可读，页面语义清晰，支持搜索引擎索引。
文章允许插入具有来源和使用依据的媒体；外部视频不可访问时仍提供完整文字与原链接。初期不依赖 AI 生成新闻配图，不提供会员、评论、用户投稿、付费内容、聊天机器人或商务撮合。
管理端：查看候选/草稿/发布状态、任务日志与错误；手动触发一次任务、暂停/恢复、撤回、重试、更正文章、调整来源与频次。通过 SSH 隧道访问，不暴露公共管理入口。管理操作不要求懂数据库或直接修改服务器文件。
视觉风格留作独立的简短视觉确认，不让名称和配色阻塞登录、源站与发布流程验证。

## 8. 部署、安全与恢复

应用数据、站点生成目录和 Codex 认证目录分开，凭据不进 Git、网页、任务日志或备份下载接口。Codex 使用非 root 专用账户、受限工作目录和最小权限；生成程序没有 Nginx 配置及系统服务管理权限。
确定性发布进程负责验证并接收生成结果；AI 不直接写公开站点目录。渲染清理不可信 HTML，不执行候选内容中的脚本。公开前台主要由 Nginx 直接提供静态资源。
使用独立 SQLite 文件，不动现有 MariaDB。记录任务版本、来源和文章版本；数据库和内容每日备份保留 7 天。初期备份仅在本机，不能防 VPS 整机丢失；异地备份未纳入已确认范围。
保留上一次可用静态站点，构建成功后原子发布，失败保留旧站；撤回文章时更新索引、RSS 和 sitemap。

## 9. 验收要求

- 两域名经公网可访问，HTTPS 有效，www/HTTP 正确跳转，无循环；源站与代理之间使用有效证书验证。
- 手机上能阅读完整精选文章；分类、搜索、RSS 和 sitemap 使用真实已发布数据。
- 使用当前账号完成至少一次“真实来源 → 草稿 → 核验 → 发布”链路，明确消耗来自订阅而非未经同意的 API。
- 重复事件不重复发布；无证据事实和异常输出进入待处理；外来指令不能改变操作权限。
- 模拟额度/登录/网络失败以及进程重启，旧站仍可访问，任务不重叠、不无限重试。
- 手动暂停、撤回、重试和至少一次备份恢复可验证。
- 服务器重启后 Nginx 与计划任务按预期恢复，trojan-go 不抢端口。
