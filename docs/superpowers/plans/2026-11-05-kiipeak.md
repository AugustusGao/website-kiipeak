# KiiPeak Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Deploy the approved Chinese robotics publication and independent VPS editorial pipeline.
**Architecture:** Python/SQLite ingestion and rendering; Nginx static site; isolated Codex process producing JSON; loopback management app; systemd timers.
**Tech Stack:** Python 3.12 on Ubuntu 24.04 ARM64, Jinja2, requests, BeautifulSoup, feedparser, standard-library HTTP management, official Codex CLI, Nginx, Certbot.
**Spec:** docs/superpowers/specs/2026-11-05-kiipeak-design.md

## Global Constraints
- Asia/Shanghai editorial starts at 05:00 and 20:00; max one post per batch/two per day.
- No paid API fallback; first device login requires user action.
- Public static site and local-only admin; no credentials in source or public files.
- Build and verify in current new feat/kiipeak repository; no preexisting code/branch to isolate.
- User explicitly requested implementation; proceed inline without an additional plan approval gate.

## Review Focus
- Untrusted source URLs or redirect chains must not reach private networks.
- Missing evidence, model failure or invalid JSON must not publish an article.
- Reload/reboot and duplicate batch requests must not double publish or exceed limits.
- Unsafe article text must remain inert; admin mutations must resist cross-site requests.
- Withdrawal and failed rendering must preserve a coherent searchable public site.
